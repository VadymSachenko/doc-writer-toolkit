This document covers how to link to other documents, sections, and resources so readers can easily find more information.

For the full version of the guidelines, see the "Linking" section in the [Google developer documentation style guide](https://developers.google.com/style) sidebar.

## Refer to other documents

**Rule:** Use _see_ to refer to links and cross-references.

**Rule:** Use meaningful link text that describes the target. Don't use generic phrases like "here" or "document".

- ✓ **Recommended:** For more information about how to use ICU syntax in WellFunnel Builder, see [<link to Translation key variables>].
- ⛔️ **Not recommended:** See this [document](<link to Translation key variables>).
- ⛔️ **Not recommended:** Click [here](<link to Translation key variables>).

**Rule:** Don't provide duplicate links to the same document within a single page. It's OK to add a secondary link if it points to a specific section of another page.

**Rule:** Use _about_ instead of _on_ when introducing a cross-reference.

- ✓ **Recommended:** For more information about product codes, see [<link to Product codes>].
- ⛔️ **Not recommended:** For more information on product codes, see [<link to Product codes>].

**Rule:** When linking to another section on the same page, tell the reader that the link goes to a section on the current page.

- ✓ **Recommended:** For more information, see the [Code in text](#code-in-text) section of this document.

For more details about cross-references, see the [Cross-references](https://developers.google.com/style/cross-references) page in the Google developer documentation style guide.
