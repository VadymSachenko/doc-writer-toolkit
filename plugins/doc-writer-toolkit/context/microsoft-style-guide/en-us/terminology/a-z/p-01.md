# Microsoft terms: P (1)

Load this file only when checking one of the indexed terms below.

<a id="p-code"></a>
## p-code

- Abbreviation for pseudocode.
- Write in full on the first mention.
- Write with capitals as P-code when it's the first word in a sentence.
- Prefer only in content for a technical audience.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/p-code)

<a id="page"></a>
## page

- Prefer page or webpage to describe one of a collection of web documents that make up a website.
- Prefer page to refer to the page the reader is on or to a specific page, such as the home page or start page.
- In a wizard, use page instead of screen to refer to an individual screen.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/page)

<a id="palette"></a>
## palette

- Prefer to describe a collection of colors or patterns that the customer can apply to objects.
- Most of the time, avoid talking about UI elements.
- Instead, talk about what the customer needs to do.
- When you must refer to a palette by name, use bold formatting for the name of the palette.
- Prefer sentence-style capitalization unless you need to match the UI.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/palette)

<a id="pane"></a>
## pane

- Use pane for a distinct UI region. Say that controls or content are in the pane; avoid blade.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/pane)

<a id="parameter"></a>
## parameter

- Prefer for a value given to a variable until an operation is completed.
- Avoid this term when you mean characteristic, element, limit, or boundary.
- Related guidance: argument vs. parameter.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/parameter)

<a id="parent-child"></a>
## parent/child

- Acceptable: parent/child in content for a technical audience to refer to the relationships among processes in a multitasking environment or in content about databases to describe the relationships among nodes in a tree structure.
- Avoid this term as a synonym for a master/subordinate relationship.
- Related guidance: master/slave, master/subordinate.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/parent-child)

<a id="parenthesis-parentheses"></a>
## parenthesis, parentheses

- Prefer opening parenthesis or closing parenthesis for an individual parenthesis, not open parenthesis, close parenthesis, beginning parenthesis, ending parenthesis, left parenthesis, or right parenthesis.
- Acceptable: parenthesis by itself if it doesn't matter or it's clear which parenthesis is being discussed.
- Related guidance: Formatting punctuation.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/parenthesis-parentheses)

<a id="passwordless"></a>
## passwordless

- Avoid.
- Instead, use wording that's friendlier and more clearly describes the benefit.
- When you must use passwordless, don't include a hyphen, and use it only as an adjective, not as a noun.
- For example, use "the steps to a passwordless environment" not "the steps to passwordless."
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/passwordless)

<a id="path"></a>
## path

- Prefer path instead of pathname, both in general references and in syntax.
- Prefer path to refer to a drive and any folders below the root directory.
- When a path also specifies a file, use full path.
- In command syntax, use path to represent only the folder portion of the full path:
- Copy \[drive:\]\[path\]filename
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/path)

<a id="per"></a>
## per

- Acceptable: per to mean for each in statistical or technical contexts.
- In other contexts, use a or the phrase for each instead of per.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/per)

<a id="percent-percentage"></a>
## percent, percentage

- One word.
- Write in full unless space is constrained.
- When spelling out percent, insert a space between the number and the word.
- Acceptable: the percent sign (%):
- In data-intensive content, such as tables, charts, and dashboards. - To save space in UI (such as in controls). - As a technical symbol.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/percent-percentage)

<a id="perimeter-network"></a>
## perimeter network

- On the first mention, use:
- Perimeter network (also known as DMZ, demilitarized zone, and screened subnet)
- After that, just use perimeter network.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/perimeter-network)

## peripheral

- Related guidance: Computer and device term collection.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/peripheral)

<a id="permissions"></a>
## permissions

- Prefer only to refer to operations associated with a specific shared resource, such as a file, directory, or printer, that are authorized by the system administrator for individual user accounts or administrative groups.
- Permissions are granted or assigned, not allowed.
- If you refer to a named permission, use title-style capitalization and regular type.
- Avoid privileges or permission records as a synonym for permissions.
- Source: [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/p/permissions)
