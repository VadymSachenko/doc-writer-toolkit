# Заголовки, типографіка й посилання на UI

## Заголовки

- Інструкції в довідці формулюйте в наказовому способі.
- Заголовки *How to…*, *Working with…*, *Using…* за можливості передавайте
  іменником або назвою процесу: *How to find* → **Пошук**; *Working with tables*
  → **Робота з таблицями**.
- У заголовку з ієрархією UI подавайте компоненти в порядку дії: меню → команда →
  вкладка → кнопка/діалогове вікно, навіть якщо англійське джерело має інший лад.
- *Function example* → **Приклад функції…**. Для довідкових заголовків зберігайте
  усталені моделі: **Примітки**, **Див. також**, **Виправлення неполадок**.
- На статтю можна посилатися перекладеною назвою, якщо вона точна, або описово,
  якщо так природніше чи менше повторів.

## Типографіка

- Точну видиму назву UI зберігайте без відмінювання, якщо вона виділена жирним;
  за потреби додайте дескриптор.
- У документації назви меню, команд, вкладок, полів і кнопок оформлюйте жирним,
  якщо це відповідає шаблону документа. Назви вікон можуть бути в лапках.
- Введення користувача — моноширинне або жирне за шаблоном; заповнювач — курсив;
  код — моноширинний; команди й параметри командного рядка — кодове оформлення.
- Не змішуйте програмні лапки та документаційні лапки; див.
  `../language-standards/punctuation-localization.md`.
- Для вступної мітки на кшталт **Примітка.** крапку робіть частиною жирного
  оформлення; наступне речення починайте з великої літери.

## Посилання на UI

- Називайте компонент так, як він показаний у продукті, і добирайте правильний
  дескриптор: **кнопка**, **прапорець**, **посилання**, **піктограма**, **команда**,
  **пункт**, **параметр**.
- Дії: кнопку **натисніть**; прапорець **установіть/зніміть**; команду, пункт або
  параметр **виберіть**; піктограму **клацніть/торкніться**; за вебпосиланням
  **перейдіть**.
- Спочатку називайте контейнер, потім дію: **У меню «Файл» виберіть команду
  «Зберегти»**.
- Не вставляйте прислівник між дієсловом і назвою команди, якщо це ускладнює
  розпізнавання UI.
