# Step-by-step instructions

## Decide whether steps are needed

Prefer self-explanatory UI, a single direct instruction, or an effective visual when it
solves the task better than a procedure. Use numbered steps for an actual sequence.

## Rules

- Give the procedure a short, action-oriented heading and use parallel headings nearby.
- Do not add an introduction that merely repeats the heading.
- State prerequisites and the starting location before the first dependent action.
- Use a numbered list for multiple steps. A standalone single action may be prose or a
  bullet when consistency requires procedure formatting.
- Put one instruction in each step. Combine short actions only when they occur in the
  same place and separating them would make the sequence harder to follow.
- Begin with an imperative verb unless a brief location phrase must come first.
- Use complete sentences, initial capitalization, and periods.
- Include the action that commits or completes the task, such as **Apply** or **OK**.
- Keep the procedure short enough to scan. Split long procedures into meaningful phases
  instead of enforcing an arbitrary number.
- Put results, explanations, or consequences after the action they describe.
- Do not interrupt a sequence with unrelated commentary.

**Recommended**

1. In **Settings**, select **Notifications**.
2. Turn on **Weekly summary**.
3. Select **Save**.

## Compact UI paths

Use `>` only when every item follows one clear selection path. Put one space on each
side and do not bold the symbol.

**Recommended:** Select **Settings** > **Notifications** > **Weekly summary**.  
**Avoid:** Mixing actions such as opening a file, choosing an option, and entering text
in one `>` path.

Because screen readers may omit the separator, use explicit steps if the path could be
ambiguous.
