# Alternative input methods

- Document supported keyboard interactions even when access keys appear in the UI.
- Provide a central explanation of mouse, keyboard, touch, pen, voice, controller, and
  other supported methods when procedures use input-neutral verbs.
- List alternative methods in a predictable order throughout the product.
- Do not present a mouse-and-key combination as if it were a keyboard shortcut. Write
  the held key and mouse action explicitly.
- Use separate columns or clearly labeled alternatives when entire procedures differ.
- Put a one-step alternative after the primary action or in a separate paragraph.
- Use bullets when a single step contains several genuine choices.

## Touch- and pen-specific terms

- **tap**, **double-tap**: select with one or two quick contacts; do not add *on*.
- **tap and hold**: use only for an interaction that requires holding contact.
- **pan**: move through content at a controlled rate in multiple directions.
- **flick**: make a quick finger movement to move through items.
- **swipe**: use only in touch-specific instructions for the product's defined gesture.
