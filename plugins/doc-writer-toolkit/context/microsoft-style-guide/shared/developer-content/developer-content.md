# Developer content

- Keep the Microsoft voice: technical content can be precise without becoming stiff.
- Assume the audience's stated prerequisite knowledge; do not reteach fundamentals that
  are outside the task.
- Explain product-specific behavior, constraints, decisions, and consequences.
- Use reference documentation for exhaustive element facts and code examples for use.
- Distinguish normative syntax from explanatory prose.
- Use the product's canonical identifiers and capitalization exactly.
