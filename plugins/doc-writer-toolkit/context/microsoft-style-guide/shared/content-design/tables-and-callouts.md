# Tables, sidebars, and pull quotes

## Tables

- Use a table only for information with at least two meaningful rows and two columns.
  Use a list for a single set of similar items.
- Introduce the table with a complete sentence when its purpose is not self-evident.
- Put the row identifier in the leftmost column.
- Keep entries parallel within each column.
- Use *None* or *Not applicable* instead of an empty cell or dash.
- Use concise, specific headers and mark the header row semantically.
- Keep headers visible or repeat them in long tables.
- Do not make a column heading combine with each cell to form a sentence; this is hard
  to scan and localize.
- Use sentence case. End cell text only when it is a sentence or the column mixes
  sentences and fragments.
- Limit columns and cell length so the table remains usable on narrow screens.

## Sidebars

Use a sidebar for short, related, nonessential information in longer content. Do not
put sequential steps, prerequisites, warnings, or information required to understand
the main text in a sidebar.

## Pull quotes

Use pull quotes sparingly. Keep them short and preserve their wording. Attribute a
quotation with the speaker's name and relevant role unless the entire content is
unambiguously about that person.
