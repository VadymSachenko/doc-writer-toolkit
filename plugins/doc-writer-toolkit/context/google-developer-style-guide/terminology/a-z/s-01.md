# S terminology — 1 of 3

Scope labels are cumulative. `general` means no product-only marker was
present; a project-specific rule can still override this entry.

<a id="term-saas"></a>
## `SaaS`

**Scope:** `general`  
**Rule:** Write out on first mention: software as a service (SaaS).

[Official entry](https://developers.google.com/style/word-list#saas)

<a id="term-sane"></a>
## `sane`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer a word like valid or sensible.

[Official entry](https://developers.google.com/style/word-list#sane)

<a id="term-sanity-check"></a>
## `sanity check`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer a term like quick check, confidence check, preliminary check or coherence check.

[Official entry](https://developers.google.com/style/word-list#sanity-check)

<a id="term-sap"></a>
## `SAP`

**Scope:** `general`  
**Rule:** Pronounced as the individual letters S, A, P, so write an SAP system, not a SAP system.

[Official entry](https://developers.google.com/style/word-list#sap)

<a id="term-scale"></a>
## `scale`

**Scope:** `general`  
**Rule:** Do not use scale alone to say that something is large or increasing. Include supporting words to indicate magnitude or direction of change in magnitude, whether scaling up or down, such as when you change a machine type to add or remove CPUs or RAM, or scaling out or in, such as adding or removing instances from a group.

[Official entry](https://developers.google.com/style/word-list#scale)

<a id="term-screenshot"></a>
## `screenshot (noun)`

**Scope:** `general`  
**Rule:** Use **screenshot**, not **screen shot** or **screensnap**. Use it as a noun; write
**take a screenshot** instead of using it as a verb.

[Official entry](https://developers.google.com/style/word-list#screenshot)

<a id="term-scroll"></a>
## `scroll`

**Scope:** `general`  
**Rule:** **Scroll** is acceptable as a verb, but prefer an implementation-neutral action
such as **go to the section**. If **scroll** is necessary, omit directional language such
as **up** or **down**.

[Official entry](https://developers.google.com/style/word-list#scroll)

<a id="term-search"></a>
## `Search (as part of product name)`

**Scope:** `general`  
**Rule:** Capitalize Search For a product like Google Search.

[Official entry](https://developers.google.com/style/word-list#search)

<a id="term-search-console"></a>
## `Search Console`

**Scope:** `general`  
**Rule:** Capitalize each word in Search Console.

[Official entry](https://developers.google.com/style/word-list#search-console)

<a id="term-see"></a>
## `see`

**Scope:** `general`  
**Rule:** OK as a general term and For links and cross-references. Our research indicates that language relating to sight is OK for a wide range of readers.

[Official entry](https://developers.google.com/style/word-list#see)

<a id="term-select"></a>
## `select`

**Scope:** `general`  
**Rule:** Use to describe choosing an item from among multiple options, selecting text, or marking a checkbox.

[Official entry](https://developers.google.com/style/word-list#select)

<a id="term-sensitive"></a>
## `sensitive`

**Scope:** `general`  
**Rule:** Sensitive data is data for which the release might be harmful. See confidential.

[Official entry](https://developers.google.com/style/word-list#sensitive)

<a id="term-service"></a>
## `service`

**Scope:** `general`  
**Rule:** You may refer to Google products, such as Google Kubernetes Engine or Compute Engine, as services. However, if the term services leads to ambiguity, then use the product names.

[Official entry](https://developers.google.com/style/word-list#service)

<a id="term-service-level-agreement"></a>
## `service level agreement`

**Scope:** `general`  
**Rule:** Lowercase For service level agreements in general. Acceptable to use title case (Service Level Agreement) For a specific document. Acceptable to abbreviate as SLA after first use.

[Official entry](https://developers.google.com/style/word-list#service-level-agreement)

<a id="term-service-level-indicator"></a>
## `service level indicator`

**Scope:** `general`  
**Rule:** Lowercase except at the beginning of a sentence, heading, or list item. Acceptable to abbreviate as SLI after first use.

[Official entry](https://developers.google.com/style/word-list#service-level-indicator)

<a id="term-service-level-objective"></a>
## `service level objective`

**Scope:** `general`  
**Rule:** Lowercase except at the beginning of a sentence, heading, or list item. Acceptable to abbreviate as SLO after first use.

[Official entry](https://developers.google.com/style/word-list#service-level-objective)

<a id="term-setup"></a>
## `setup (noun or adjective), set up (verb)`

**Scope:** `general`  
**Rule:** Use this spelling and form unless a project-specific rule overrides it.

[Official entry](https://developers.google.com/style/word-list#setup)

<a id="term-sexy"></a>
## `sexy`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer precise, positive words, such as fast, powerful, or elegant.

[Official entry](https://developers.google.com/style/word-list#sexy)

<a id="term-sha-1"></a>
## `SHA-1`

**Scope:** `general`  
**Rule:** Use the heading form; do not use SHA1, except in string literals/enums and in hyphenated phrases such as HSA-SHA1.

[Official entry](https://developers.google.com/style/word-list#sha-1)

<a id="term-shall"></a>
## `shall`

**Scope:** `use-with-caution`  
**Rule:** Avoid shall except under advice from a lawyer.

[Official entry](https://developers.google.com/style/word-list#shall)
