# E terminology — 1 of 2

Scope labels are cumulative. `general` means no product-only marker was
present; a project-specific rule can still override this entry.

<a id="term-each"></a>
## `each`

**Scope:** `general`  
**Rule:** Each refers to every individual item taken individually, not to a group of items taken collectively. In other words, each isn't a synonym for all. For example, a list of each item is ambiguous; a list of all the items or a list of the items is generally clearer.

[Official entry](https://developers.google.com/style/word-list#each)

<a id="term-earlier"></a>
## `earlier`

**Scope:** `general`  
**Rule:** Use for a range of version numbers, not lower. In Android documentation, do not use earlier for a range of version numbers. Prefer lower. For a position in a document, use earlier or preceding, not higher.

[Official entry](https://developers.google.com/style/word-list#earlier)

<a id="term-easy"></a>
## `easy, easily`

**Scope:** `use-with-caution`  
**Rule:** What might be easy for you might not be easy for others. Try eliminating this word from the sentence because usually the same meaning can be conveyed without it.

[Official entry](https://developers.google.com/style/word-list#easy)

<a id="term-eg"></a>
## `e.g.`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer phrases like for example or such as. Many people confuse e.g. and i.e.

[Official entry](https://developers.google.com/style/word-list#eg)

## `egress`

[Official entry](https://developers.google.com/style/word-list#egress)

<a id="term-either"></a>
## `either`

**Scope:** `general`  
**Rule:** When using either, use parallel syntax. In general, use either only for a choice between two things, not for a choice among multiple things. Writing either A or B or C will distract some readers, but if it's the best phrasing for your situation, then use it.

[Official entry](https://developers.google.com/style/word-list#either)

<a id="term-element"></a>
## `element`

**Scope:** `general`  
**Rule:** In HTML and XML, a tag is a component of an element that indicates the start or end of the element. (For example, the <i> start tag indicates the beginning of the <i>example</i> element.) In general, do not use the term tag to refer to an entire element.

[Official entry](https://developers.google.com/style/word-list#element)

<a id="term-email"></a>
## `email`

**Scope:** `general`  
**Rule:** Use the heading form; do not use e-mail, Email, or E-mail. Do not use as a verb. Use a specific verb in front of the word. For example, send email. This construction is better for translation and a global audience.

[Official entry](https://developers.google.com/style/word-list#email)

## `emoji`

**Scope:** `general`

[Official entry](https://developers.google.com/style/word-list#emoji)

<a id="term-enable"></a>
## `enable`

**Scope:** `general`  
**Rule:** In procedures, use the appropriate label and action for the UI element that the user interacts with. When describing a user action or the state of a UI element, use a more precise term where possible. Acceptable to use enable when not referring to a person. For turning on or activating an option or feature, use enable or turn on consistently: Use the same term in introductory text as described in the procedure. For making something feasible to do (not turning a setting on or off), use lets you instead: *The API lets you detect features in images*, not *The API enables you to detect features in images*.

[Official entry](https://developers.google.com/style/word-list#enable)

<a id="term-error-prone"></a>
## `error-prone (adjective)`

**Scope:** `general`  
**Rule:** Hyphenate. Lowercase except at the beginning of a sentence, heading, or list item.

[Official entry](https://developers.google.com/style/word-list#error-prone)

<a id="term-etc"></a>
## `etc.`

**Scope:** `use-with-caution`  
**Rule:** Avoid using etc., and so forth, and and so on wherever possible. If you really need to use one, use etc. Always include the period, even if a comma follows immediately after.

[Official entry](https://developers.google.com/style/word-list#etc)

<a id="term-eventually"></a>
## `eventually`

**Scope:** `use-with-caution`  
**Rule:** Avoid in timeless documentation because this word can become outdated. The word can also prematurely disclose product or feature strategy or inappropriately imply that a product or feature might change.

[Official entry](https://developers.google.com/style/word-list#eventually)

<a id="term-execute"></a>
## `execute`

**Scope:** `general`  
**Rule:** Verb commonly used to refer to function calls, SQL queries, and other processes. When the meaning is the same, use the simpler word run instead. If you need to use a more precise term for your context, use that term.

[Official entry](https://developers.google.com/style/word-list#execute)

<a id="term-expander-arrow"></a>
## `expander arrow`

**Scope:** `general`  
**Rule:** The UI element used to expand or collapse a section of navigation or content. If you describe this element, use the terms expander arrow and expandable section Do not use terms like expando or zippy.

[Official entry](https://developers.google.com/style/word-list#expander-arrow)
