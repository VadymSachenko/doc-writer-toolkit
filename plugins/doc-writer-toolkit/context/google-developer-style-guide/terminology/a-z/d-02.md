# D terminology — 2 of 3

Scope labels are cumulative. `general` means no product-only marker was
present; a project-specific rule can still override this entry.

<a id="term-developers-console"></a>
## `Developers Console`

**Scope:** `do-not-use`  
**Rule:** Do not use.

[Official entry](https://developers.google.com/style/word-list#developers-console)

<a id="term-devops"></a>
## `DevOps`

**Scope:** `general`  
**Rule:** Short for development operations. No need to spell out on first mention unless the audience requires it.

[Official entry](https://developers.google.com/style/word-list#devops)

<a id="term-dialog"></a>
## `dialog`

**Scope:** `general`  
**Rule:** Use dialog for the UI element sometimes called a dialog box. Use dialogue only for verbal interaction between people.

[Official entry](https://developers.google.com/style/word-list#dialog)

<a id="term-directory"></a>
## `directory, folder`

**Scope:** `general`  
**Rule:** If the context that you're documenting (such as an IDE's GUI) uses one term or the other, use that term. If not, then use directory in a command-line context, and folder in a GUI context. When in doubt, default to directory.

[Official entry](https://developers.google.com/style/word-list#directory)

<a id="term-disable"></a>
## `disable`

**Scope:** `use-with-caution`  
**Rule:** Do not use disable or disabled to describe something that's broken. When describing a user action or the state of a UI element, use a more precise term where possible. You can use inactive, unavailable, deactivate, turn off, or deselect, depending on the context. Use the same term consistently throughout your document.

[Official entry](https://developers.google.com/style/word-list#disable)

<a id="term-disclosure-triangle"></a>
## `disclosure triangle, disclosure widget`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer expander arrow.

[Official entry](https://developers.google.com/style/word-list#disclosure-triangle)

<a id="term-display"></a>
## `display (verb)`

**Scope:** `general`  
**Rule:** Do not use as an intransitive verb. Display is a transitive verb; therefore, it requires an object. It is often misused in technical documentation, as demonstrated by the following example: The following example demonstrates correct usage of the verb display but means something quite different from the preceding examples.

[Official entry](https://developers.google.com/style/word-list#display)

<a id="term-documentation"></a>
## `documentation or document or documents`

**Scope:** `general`  
**Rule:** To refer specifically to the text on a page that explains a product, feature, or service, use this document, and not this article, this topic, this doc, or this page. Acceptable to use this tutorial, this quickstart, or this codelab for those specific documentation types. Always spell out documentation except in cases where space is limited, such as in tabs and URLs.

[Official entry](https://developers.google.com/style/word-list#documentation)

<a id="term-does-not-yet"></a>
## `does not yet`

**Scope:** `use-with-caution`  
**Rule:** Avoid in timeless documentation because this phrase can become outdated. The phrase can also prematurely disclose product or feature strategy or inappropriately imply that a product or feature might change.

[Official entry](https://developers.google.com/style/word-list#does-not-yet)

<a id="term-downscope"></a>
## `downscope`

**Scope:** `use-with-caution`  
**Rule:** Consider using a more descriptive term like constrain scope or reduce scope. Because downscope might not be broadly understood, if you use the term, make sure to define it on first use. Do not use down scope or down-scope

[Official entry](https://developers.google.com/style/word-list#downscope)

<a id="term-drag"></a>
## `drag`

**Scope:** `general`  
**Rule:** Use drag, not click and drag and not drag and drop. Acceptable drag-and-drop as an adjective.

[Official entry](https://developers.google.com/style/word-list#drag)

<a id="term-drop-down"></a>
## `drop-down`

**Scope:** `use-with-caution`  
**Rule:** In most cases, you can omit drop-down from phrases like drop-down list or drop-down menu, and just use list or menu. Include drop-down as a modifier only if the omission would cause ambiguity. Do not use drop-down as a standalone noun.

[Official entry](https://developers.google.com/style/word-list#drop-down)
