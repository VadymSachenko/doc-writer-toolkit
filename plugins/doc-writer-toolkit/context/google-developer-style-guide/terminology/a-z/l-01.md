# L terminology — 1 of 2

Scope labels are cumulative. `general` means no product-only marker was
present; a project-specific rule can still override this entry.

<a id="term-lame"></a>
## `lame`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer precise, non-figurative language to refer to a deficiency in a component.

[Official entry](https://developers.google.com/style/word-list#lame)

<a id="term-later"></a>
## `later`

**Scope:** `general`  
**Rule:** Use for a range of version numbers, not higher. In Android documentation, do not use later for a range of version numbers. Prefer higher. For a position in a document, use later or following, not below.

[Official entry](https://developers.google.com/style/word-list#later)

<a id="term-latest"></a>
## `latest`

**Scope:** `use-with-caution`  
**Rule:** Avoid in timeless documentation because this word can become outdated. If you must use latest, give the reader a reference point—for example, a version number or release date.

[Official entry](https://developers.google.com/style/word-list#latest)

<a id="term-learnings"></a>
## `learnings`

**Scope:** `do-not-use`  
**Rule:** Do not use. Instead, refer to knowledge or things that you learned.

[Official entry](https://developers.google.com/style/word-list#learnings)

<a id="term-left-nav"></a>
## `left-nav, right-nav`

**Scope:** `do-not-use`  
**Rule:** Do not use directional language. If referring to applications, use navigation menu. If referring to navigational elements for documentation, use content navigation menu.

[Official entry](https://developers.google.com/style/word-list#left-nav)

<a id="term-legacy"></a>
## `legacy`

**Scope:** `general`  
**Rule:** If possible, use a more precise term. If you do use legacy, include or point to a definition to clarify what you mean in the current context. Do not use legacy with any sort of pejorative connotation.

[Official entry](https://developers.google.com/style/word-list#legacy)

<a id="term-lets"></a>
## `let's (as a contraction of let us)`

**Scope:** `do-not-use`  
**Rule:** Do not use if at all possible.

[Official entry](https://developers.google.com/style/word-list#lets)

<a id="term-loa-cfa"></a>
## `Letter of Authorization and Connecting Facility Assignment (LOA-CFA)`

**Scope:** `general`  
**Rule:** Write out and capitalize each word on first use. Acceptable to abbreviate as LOA-CFA after first use.

[Official entry](https://developers.google.com/style/word-list#loa-cfa)

<a id="term-leverage"></a>
## `leverage`

**Scope:** `use-with-caution`  
**Rule:** Avoid using if you mean use. If possible, use a more precise term. For example, use, build on, or take advantage of.

[Official entry](https://developers.google.com/style/word-list#leverage)

<a id="term-lifecycle"></a>
## `lifecycle`

**Scope:** `general`  
**Rule:** Use the heading form; do not use life cycle or life-cycle.

[Official entry](https://developers.google.com/style/word-list#lifecycle)

<a id="term-lift-and-shift"></a>
## `lift and shift`

**Scope:** `general`  
**Rule:** See rehost.

[Official entry](https://developers.google.com/style/word-list#lift-and-shift)

<a id="term-like"></a>
## `like`

**Scope:** `general`  
**Rule:** Acceptable to use like for either drawing comparisons (in the sense of similar to) or introducing examples (in the sense of such as).

[Official entry](https://developers.google.com/style/word-list#like)

<a id="term-limits"></a>
## `limits`

**Scope:** `general`  
**Rule:** In an API context, limit often refers to usage limits (number of queries allowed per second or per day). Where possible, specify the kind of limit that you mean, such as usage limit or service limit; the word limit can refer to many different kinds of limits, including rules about acceptable use.

[Official entry](https://developers.google.com/style/word-list#limits)

<a id="term-lint"></a>
## `lint`

**Scope:** `general`  
**Rule:** Write both command-line tool name and command in lowercase. Use code font except where inappropriate.

[Official entry](https://developers.google.com/style/word-list#lint)

<a id="term-little-endian"></a>
## `little-endian`

**Scope:** `general`  
**Rule:** Hyphenate. Lowercase except at the beginning of a sentence, heading, or list item.

[Official entry](https://developers.google.com/style/word-list#little-endian)

<a id="term-livestream"></a>
## `livestream`

**Scope:** `general`  
**Rule:** Use the heading form; do not use live stream.

[Official entry](https://developers.google.com/style/word-list#livestream)

<a id="term-load-balancing"></a>
## `load balancing (noun), load-balancing (adjective)`

**Scope:** `general`  
**Rule:** Spell as load balancing when used as a noun and as load-balancing when used as an adjective.

[Official entry](https://developers.google.com/style/word-list#load-balancing)

<a id="term-lock-screen"></a>
## `lock screen`

**Scope:** `general, android-only`  
**Rule:** Two words in Android contexts; not lockscreen or lock-screen.

[Official entry](https://developers.google.com/style/word-list#lock-screen)

<a id="term-login"></a>
## `login (noun or adjective), log in (verb)`

**Scope:** `general`  
**Rule:** For the verb form, sign in is generally better. If you're documenting a tool that uses the term log in, then use that term.

[Official entry](https://developers.google.com/style/word-list#login)

<a id="term-long-press"></a>
## `long press`

**Scope:** `do-not-use, android-only`  
**Rule:** In Android documentation, do not use. Prefer touch & hold. (Not touch and hold.)

[Official entry](https://developers.google.com/style/word-list#long-press)
