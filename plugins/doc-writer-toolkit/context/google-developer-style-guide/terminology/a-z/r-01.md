# R terminology — 1 of 1

Scope labels are cumulative. `general` means no product-only marker was
present; a project-specific rule can still override this entry.

<a id="term-rdp"></a>
## `RDP`

**Scope:** `general`  
**Rule:** Do not use as a verb. Prefer connect using RDP. If it's clear from context that they're using RDP, Acceptable to use connect.

[Official entry](https://developers.google.com/style/word-list#rdp)

**Rule:** See guidance about hyphens with prefixes.

[Official entry](https://developers.google.com/style/word-list#re)

<a id="term-redline"></a>
## `redline`

**Scope:** `do-not-use`  
**Rule:** Do not use as a verb. Prefer precise terms appropriate to the context. In the context of editing or providing a review, refer to those actions or to tracking changes. In the context of setting priorities and planning work, refer to those actions or to priority lining.

[Official entry](https://developers.google.com/style/word-list#redline)

<a id="term-regex"></a>
## `regex`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer regular expression.

[Official entry](https://developers.google.com/style/word-list#regex)

<a id="term-rehost"></a>
## `rehost`

**Scope:** `general`  
**Rule:** Use to describe the migration of an app or workload with no changes or minimal changes to that app or workload. Also known as lift and shift. On first mention, associate rehost with lift and shift. Okay to use rehosting as needed after first mention. Do not use the forklift approach.

[Official entry](https://developers.google.com/style/word-list#rehost)

**Scope:** `do-not-use`

<a id="term-retriable"></a>
## `retriable, triable`

**Scope:** `do-not-use`  
**Rule:** Do not use retriable or triable, unless a code item uses that spelling. Outside of code font, write around the term.

[Official entry](https://developers.google.com/style/word-list#retriable)

<a id="term-retryable"></a>
## `retryable, tryable`

**Scope:** `use-with-caution`  
**Rule:** Where possible, write around retryable and tryable. For example, write out you can try it again or can be tried again.

[Official entry](https://developers.google.com/style/word-list#retryable)

<a id="term-review"></a>
## `review`

**Scope:** `general`  
**Rule:** If you mean "read, potentially for the first time," then use read instead of review. If you mean "read critically, commenting on problems" (as in code review), then review is fine. Avoid using phrasing like "If you've never heard of OAuth, then review the OAuth documentation."

[Official entry](https://developers.google.com/style/word-list#review)

<a id="term-rfc"></a>
## `RFC`

**Scope:** `general`  
**Rule:** When referencing an RFC specification, use a space between RFC and the number (for example, RFC 2318).

[Official entry](https://developers.google.com/style/word-list#rfc)

<a id="term-roll-out"></a>
## `roll out`

**Scope:** `use-with-caution`  
**Rule:** Do not use to mean a sudden or instantaneous launch. If you use roll out, define what you mean. When possible, use a more precise, non-figurative term like gradual, in stages, phases, or progressive.

[Official entry](https://developers.google.com/style/word-list#roll-out)

<a id="term-runtime"></a>
## `runtime, run time`

**Scope:** `general`  
**Rule:** Use the noun runtime For the environment in which software runs, such as a Ruby or Java runtime. Use the noun phrase run time For the time during program execution when something occurs, as contrasted with compile time, for example.

[Official entry](https://developers.google.com/style/word-list#runtime)
