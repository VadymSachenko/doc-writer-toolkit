# Safe and inclusive example data

## GDSG-EXAMPLE-001 — Use reserved, fictional data

- Never expose a real person’s name, email, phone number, account, token, password,
  address, customer data, or production identifier.
- Use `example.com`, `example.net`, or `example.org` for documentation domains.
- Use standards-reserved IP address blocks and other project-approved fictional values.
- Make project, service, bucket, and account identifiers obviously illustrative and valid
  for the syntax being demonstrated.
- Do not use placeholders that look like secrets or encourage readers to reuse an insecure
  credential.

## GDSG-EXAMPLE-002 — Represent people inclusively

Use a varied set of fictional names and roles without stereotypes, jokes, assumed gender,
or culturally specific wordplay. Include identity attributes only when they are relevant
to the technical point. Prefer role descriptions such as **administrator** or **reviewer**
when a personal name adds no value.

Examples must be technically plausible, legally safe, and easy to distinguish from literal
production values.
