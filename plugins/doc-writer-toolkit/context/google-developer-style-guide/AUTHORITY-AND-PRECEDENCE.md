# Authority and precedence

Use the first applicable source in this order:

1. Project- or product-specific style and approved terminology.
2. This local Google developer documentation style corpus.
3. For an unanswered spelling question, Merriam-Webster; use the first listed form.
4. For unanswered nontechnical style, *The Chicago Manual of Style*, 17th edition.
5. For unanswered technical style, the Microsoft Writing Style Guide when its
   product-specific assumptions do not conflict with the current context.
6. Established usage in the documentation set or relevant technical community.

## Scope labels

- `general`: applies to Google-style developer documentation generally.
- `android-only`: apply only to Android documentation.
- `google-cloud-only`: apply only to Google Cloud documentation.
- `contextual`: use reader needs and technical convention to decide.
- `do-not-use`: replace or write around the term, including in editable code.
- `use-with-caution`: prefer a clearer term; retain only when context requires it.

## Deliberate deviations

Depart from a guideline when doing so materially improves accuracy or reader success.
Record the reason, follow the controlling project convention, and remain consistent
throughout the document set.

For a conflict that cannot be resolved from this hierarchy, record the terms, contexts,
sources, and decision in `maintenance/unresolved-items.md`.
