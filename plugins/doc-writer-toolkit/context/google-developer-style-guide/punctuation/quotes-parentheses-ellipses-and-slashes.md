# Quotation marks, parentheses, ellipses, and slashes

## Quotation marks

- Use straight quotation marks and apostrophes in source files unless the publishing
  system converts them safely.
- In US English, put a period or comma inside a closing quotation mark, except when the
  punctuation would incorrectly become part of a literal code string.
- Use double quotation marks first and single quotation marks for a quotation within a
  quotation.
- Do not put quotation marks around code-formatted text unless the marks are literal input.
- Do not use quotation marks merely to emphasize a word or UI label.

## Parentheses

- Put supplementary, nonessential information in parentheses; do not hide a requirement
  or critical condition there.
- Keep parenthetical text short. Rewrite nested or long parentheses.
- If a complete sentence stands entirely in parentheses, put its period inside. If the
  parenthetical is part of a sentence, put sentence punctuation outside.
- Do not use parentheses for optional plurals, alternatives, or instructional choices.

## Ellipses

Avoid ellipses in ordinary prose. In a quotation, use three periods to show an omission
within the quoted material without changing its meaning. Preserve an ellipsis in a UI
label only when omitting it would make the label inaccurate or ambiguous.

## Slashes

Avoid a slash in prose. Use words such as **and**, **or**, **per**, or a rewritten phrase.
Do not use **and/or** or slash-formatted dates. A slash is acceptable when it is literal
syntax in a URL, path, command, code expression, or other established notation.
