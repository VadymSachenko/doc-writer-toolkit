# Text formatting

## Choose formatting by meaning

| Content | Format |
|---|---|
| Named UI element | **Bold** |
| Literal code, input, output, filename, path, or technical identifier | `Code font` |
| New term at its first definition; a word used as a word | *Italic* |
| Ordinary product, feature, or organization name | Ordinary type |

- Use formatting consistently and sparingly. Do not combine styles for general emphasis.
- A literal value shown in the UI uses both bold and code formatting.
- Do not use underlining for emphasis; readers interpret it as a link.
- Do not use all caps to emphasize prose.

## GDSG-FORMAT-001 — Introduce terms deliberately

Italicize a new or unfamiliar term at its first definition when the styling helps the
reader identify the term. Do not keep italicizing later occurrences. Italicize a word
discussed as a word, but use quotation marks for an actual quotation.

## GDSG-FORMAT-002 — Place examples naturally

- Introduce a standalone example with a complete sentence and suitable punctuation,
  commonly a colon.
- Put a short, nonessential example in parentheses or after **for example**.
- Put a longer example after the claim it supports or in a separate block.
- Rewrite a sentence if **for example** creates an awkward interruption or unclear scope.

## GDSG-FORMAT-003 — Titles and letters as letters

Italicize the title of a full-length work — a book, movie, or web series — unless the
title doubles as link text. Put the title of a shorter work, such as an article or a
single episode, in quotation marks instead, with the same link-text exception.
Italicize a letter referred to as itself, such as the *'s* in a possessive.
