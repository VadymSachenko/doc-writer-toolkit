Цей глосарій є авторитетним джерелом термінів для україномовних документів UCPay. Оновлюйте
його, коли новий документ вводить новий термін, якого тут ще немає.

## Як читати таблицю

- **Термін** — канонічна форма. Заголовне слово написано з великої як словникова стаття; **у
  прозі** загальні назви пишуться з малої («платіжний метод визначає…»). Велику літеру в тексті
  зберігають лише власні назви (UniComPay, UCP) і дослівні мітки UI.
- **Рендер** — нормативне оформлення терміна в тексті. Це **обов'язковий** стовпець: рендер
  береться звідси, а не обирається на місці. Правила, що ним керують, — Ж1, Ж3, Ж4 у
  `${CLAUDE_PLUGIN_ROOT}/context/doc-rules/project-rules/formatting-conventions.md`.
- **Код-сутність** — те, як це саме поняття називається в коді чи в API. Код-сутність завжди в
  `code font` і завжди англійською, як у коді (Ж4). Порожня клітинка означає, що відповідника в
  коді немає.
- Одне поняття може мати і термін, і код-сутність — це **різні сутності**, кожна зі своїм
  рендером (Ж3). Пиши «метод квазі» про поняття і `QUASI` про константу, і не змішуй їх у межах
  однієї ролі.

**Значення стовпця «Рендер»:**

| Значення | Що означає |
|---|---|
| `текст` | звичайний текст, без виділення |
| **`жирний` (UI)** | видима мітка інтерфейсу — жирний, дослівне написання (Ж1) |
| `` `code` `` | літеральне системне значення або код-сутність — `code font` (Ж4) |
| `*курсив*` | новий термін у місці його визначення, один раз (`GDSG-FORMAT-001`) |

## Терміни

| Термін | Рендер | Код-сутність | Визначення |
|---|---|---|---|
| API-токен | `текст` | | Унікальний рядок із 128 символів для автентифікації запитів до API UCPay. Не використовуйте: партнерський токен, ключ автентифікації. |
| Архів | **жирний** (UI) | | Розділ кабінету партнера з завершеними транзакціями. Не використовуйте: завершені транзакції, закриті позиції, історія. |
| `cancelled` | `code` | `cancelled` | Статус транзакції — скасована. **UK spelling** (не `canceled`). UI-мітка: **Скасована**. |
| Вебхук | `текст` | | HTTP-запит, який UCPay надсилає на URL партнера при настанні події (наприклад, зміні статусу транзакції). Не використовуйте: колбек, нотифікація, пуш. |
| Вихідна транзакція | `текст` | | Транзакція з виведенням коштів із рахунку. Не використовуйте: виплата (як синонім у публічних документах). |
| Вхідна транзакція | `текст` | | Транзакція із зарахуванням коштів на рахунок партнера або кінцевого клієнта. Не використовуйте: поповнення, вхідна заявка. |
| Віджет | `текст` | | Платіжний компонент UCPay, що встановлюється на стороні партнера. Не використовуйте: компонент. |
| Віджет-хост | `текст` | `WidgetHost`, `WidgetMonoHost` | Хост, на якому рендериться платіжний інтерфейс для кінцевого клієнта. `WidgetHost` — звичайний віджет; `WidgetMonoHost` — окремий хост для методу квазі. У прозі — «віджет-хост»; конкретний хост називай код-сутністю. Не використовуйте: віджетний сервер, хост віджету. |
| Диспут | `текст` | | Оскарження транзакції кінцевим клієнтом. Не використовуйте: скарга, апеляція. |
| Ендпоінт | `текст` | | Конкретна адреса API-методу. Не використовуйте: кінцева точка. |
| `in queue` | `code` | `in queue` | Статус транзакції — в черзі очікування. UI-мітка: **В черзі**. |
| `in work` | `code` | `in work` | Статус транзакції — у роботі. UI-мітка: **В роботі**. |
| Кабінет партнера | `текст` | | Вебінтерфейс UCPay для керування транзакціями, налаштуваннями та звітністю. Не використовуйте: дашборд, партнерський портал, кабінет клієнта. |
| Квазі | `текст` | константа `QUASI`, значення `quasi` | Платіжний метод, що приховує реальний банк-отримувач за віджетом UCP. У прозі — «метод квазі», «квазіреквізит»; латиницею тільки як код-сутність. Не використовуйте: QUASI у прозі, quasi у прозі, «квазі» в лапках, квазі-метод через дефіс. |
| Кінцевий клієнт | `текст` | | Фізична або юридична особа, яка здійснює платіж через продукт партнера. Не використовуйте: кінцевий користувач, клієнт (коли неоднозначно). |
| Комісія | `текст` | | Сума, що утримується UCPay за проведення транзакції. Не використовуйте: збір, плата. |
| Моніторинг | **жирний** (UI) | | Розділ кабінету партнера з активними (незавершеними) транзакціями. Не використовуйте: активні транзакції, відкриті позиції. |
| `new` | `code` | `new` | Статус транзакції — нова. UI-мітка: **Новий**. |
| Партнер | `текст` | | Юридична особа, підключена до платформи UCPay для обробки платежів. Не використовуйте: провайдер, клієнт, мерчант. |
| Переміщення | `текст` | | Зміна відповідальної робочої групи для транзакції. Не використовуйте: перепризначення, переведення. |
| Платіжний метод | `текст` | query-параметр `paymentMethod`; константи `CARD`, `IBAN`, `LINK`, `QUASI`, `PHONE` | Тип платіжного реквізиту, який UCP видає у відповідь на вхідну транзакцію: картка, IBAN, посилання, квазі або телефон. Не використовуйте: payment method (англійською в прозі), метод оплати, спосіб оплати. |
| `REST Proxy` | `code` | `REST Proxy` | Модуль-посередник між бекендом UCP і банком, що стоїть за методом квазі. Назва модуля — лишається англійською, у `code font` (Ж4, Ж5). Не використовуйте: рест-проксі, REST-проксі, **REST Proxy** жирним. |
| Робоча група | `текст` | | Підрозділ, відповідальний за опрацювання транзакцій у певний момент. Не використовуйте: команда, черга. |
| Сума | `текст` | | Заявлена сума транзакції на момент ініціювання. Не використовуйте: початкова сума, заявлена сума (як альтернатива терміна). |
| `success` | `code` | `success` | Статус транзакції — успішна. UI-мітка: **Успіх**. |
| Телефон | `текст` | константа `PHONE`, значення `phone`, маркер `PHONE:` у полі `Link` | Платіжний метод, за яким UCP видає номер телефону як платіжний реквізит. У прозі — «метод телефон», «реквізит типу телефон»; латиницею тільки як код-сутність. Розм.: фон. Не використовуйте: PHONE у прозі, phone у прозі, «телефон» у лапках, «фон» поза розмовним контекстом. |
| Тип платежу | `текст` | `paymentType`; значення `HUMO`, `UZCARD`, `CLICK`, `PAYME`, `PAYNET` | Додатковий, вторинний фільтр поверх платіжного методу. Не використовуйте: payment type (англійською в прозі), тип оплати, підтип методу. |
| Токен вебхука | `текст` | | Ключ для перевірки автентичності вхідних вебхук-запитів. Не використовуйте: колбек-токен, секрет вебхука. |
| Транзакція | `текст` | | Фінансова операція, ініційована через платіжний шлюз UCPay. Розм.: заявка. Не використовуйте: запит, аплікація, операція. |

| Фактична сума | `текст` | | Остаточна сума, зафіксована після завершення транзакції. Не використовуйте: кінцева сума, підтверджена сума. |
