This document covers how to use punctuation correctly and consistently to improve the readability of your documentation.

For the full version of the guidelines, see the "Punctuation" section in the [Google developer documentation style guide](https://developers.google.com/style) sidebar.

## Em dashes

**Rule:** Do not put spaces before or after an em dash (—).

- ✓ **Recommended:** The token is displayed only once—copy it before closing the dialog.
- ⛔️ **Not recommended:** The token is displayed only once — copy it before closing the dialog.

For more details, see the [Dashes](https://developers.google.com/style/dashes) page in the Google developer documentation style guide.

## Introductory phrase preceding a colon

**Rule:** When a colon introduces a list, the text that precedes the colon must be able to stand alone as a complete sentence.

- ✓ **Recommended:** The fields are defined as follows:
- ⛔️ **Not recommended:** The fields are:

For more details, see the [Colons](https://developers.google.com/style/colons) page in the Google developer documentation style guide.

## Slashes

**Rule:** Don't use date formats that rely on slashes.

- ✓ **Recommended:** 2025-10-14
- ⛔️ **Not recommended:** 10/14/2025

**Rule:** Don't use slashes to separate alternatives. Use _or_ instead.

- ✓ **Recommended:** The permission grants read or write access.
- ⛔️ **Not recommended:** The permission grants read/write access.
- ✓ **Recommended:** A disaster relief map is not subject to the usage limits even if it has been developed or hosted by a commercial entity.
- ⛔️ **Not recommended:** A disaster relief map is not subject to the usage limits even if it has been developed/hosted by a commercial entity.

**Rule:** Don't use slashes when you need both _and_ and _or_. Avoid *and/or* except when space is limited.

- ✓ **Recommended:** You can view and edit your own data.
- ⛔️ **Not recommended:** You can view and/or edit your own data.

**Rule:** Don't use slashes with fractions because they can be ambiguous.

- ✓ **Recommended:** ¾
- ✓ **Recommended:** 0.75
- ✓ **Recommended:** 75%
- ⛔️ **Not recommended:** 3/4

**Rule:** Don't use abbreviations that rely on slashes.

- ✓ **Recommended:** care of, with
- ⛔️ **Not recommended:** c/o, w/

For more details, see the [Slashes](https://developers.google.com/style/slashes) page in the Google developer documentation style guide.

## Ampersands

**Rule:** Don't use ampersands (`&`) as conjunctions or shorthand for _and_. Use the word _and_ instead. This includes headings and navigation.

- ✓ **Recommended:** Notes and cautions
- ⛔️ **Not recommended:** Notes & cautions

**Exception:** It's OK to use _&_ when referring to a UI element or menu name that includes _&_ in its label.
