## Design rules

### Призначення

- Концептуальна тема **пояснює**, а не **інструктує**. Покрокові інструкції — у посібнику користувача.
- Обов'язковий — лише вступний огляд. Усі інші розділи вибирайте за змістом теми.
- Не дублюйте зміст посібника: посилайтеся через «Наступні кроки» або «Пов'язані документи».

### Застереження

| Тип | Коли використовувати |
|---|---|
| `:::note` | Корисна, але некритична інформація |
| `:::info` | Процесний контекст, часові рамки, уточнення |
| `:::warning` | Незворотні або небезпечні ситуації |
| `:::tip` | Альтернативний шлях, порада |

Застереження доповнюють текст, а не замінюють його.

### Діаграми

- Процеси з кількома учасниками → Mermaid `sequenceDiagram`.
- Дерева рішень → Mermaid `flowchart`.
- Рендеруйте діаграми у Docusaurus, не вставляйте знімки екрана.

### «Наступні кроки» vs «Пов'язані документи»

- **Наступні кроки**: посібники користувача, до яких читач природно перейде після розуміння концепції.
- **Пов'язані документи**: інші концептуальні теми, API-референси, архітектурні огляди.
- Якщо підходить лише один розділ — не створюйте другий.

### Термінологія

- Терміни: з глосарію `${CLAUDE_PLUGIN_ROOT}/context/doc-rules/project-rules/glossary-ua.md`.
- При першій згадці — розкривайте абревіатуру: «API-токен (Application Programming Interface)»; далі — лише скорочення.
- Статуси у `code font`: `new`, `success`, `cancelled`; **UK spelling**: `cancelled` (не `canceled`).
