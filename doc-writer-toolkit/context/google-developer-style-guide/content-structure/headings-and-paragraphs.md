# Headings and paragraphs

## GDSG-HEAD-001 — Make headings descriptive

- Use sentence case.
- For a task, use a bare infinitive such as **Configure access**.
- For a concept or reference topic, use a noun phrase such as **Access requirements**.
- Prefer a direct task verb to an **-ing** form when both are accurate.
- Avoid empty labels such as **Overview** when a specific topic name is available.
- Use an abbreviation only if the audience commonly knows it; define an unfamiliar one
  in the paragraph after the heading, not in the heading itself.

## GDSG-HEAD-002 — Preserve semantic hierarchy

Use one page-level H1. Nest headings in order without skipping levels and do not create
an empty section. Do not manually number headings unless the product’s content model
requires numbering. Refer to a group as **the following sections**, not sections “below.”

When an entire optional section is useful, make the status clear in the heading, such as
**Optional: Configure caching**. Do not mark ordinary required content optional.

## Paragraphs

- Give each paragraph one controlling idea.
- Put the conclusion, requirement, or other critical information first.
- Keep paragraphs short enough to scan. A paragraph longer than about five or six
  sentences often needs a split, list, or heading.
- Use transitions only when they clarify the logical relationship.
- Do not create one-sentence fragments solely to make the page appear shorter.
