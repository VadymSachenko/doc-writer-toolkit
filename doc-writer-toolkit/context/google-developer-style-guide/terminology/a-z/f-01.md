# F terminology — 1 of 1

Scope labels are cumulative. `general` means no product-only marker was
present; a project-specific rule can still override this entry.

<a id="term-failover"></a>
## `fail over (verb), failover (noun, adjective)`

**Scope:** `general`  
**Rule:** Use this spelling and form unless a project-specific rule overrides it.

[Official entry](https://developers.google.com/style/word-list#failover)

<a id="term-fat"></a>
## `fat`

**Scope:** `do-not-use`  
**Rule:** Do not use **fat** figuratively; name the specific property, such as
**high-capacity** or **full-featured**, or state what is removed. The acronym **FAT** is
acceptable for **file allocation table**.

[Official entry](https://developers.google.com/style/word-list#fat)

<a id="term-female-adapter"></a>
## `female adapter`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer a genderless word like socket.

[Official entry](https://developers.google.com/style/word-list#female-adapter)

<a id="term-fhir"></a>
## `Fast Healthcare Interoperability Resources (FHIR)`

**Scope:** `general`  
**Rule:** Refer to a FHIR (pronounced "a fire," as in "a FHIR store"), not an FHIR.

[Official entry](https://developers.google.com/style/word-list#fhir)

<a id="term-fill-in"></a>
## `fill in; fill out`

**Scope:** `general`  
**Rule:** Use **fill in** for individual fields and **fill out** for an entire form.

[Official entry](https://developers.google.com/style/word-list#fill-in)

<a id="term-final-solution"></a>
## `final solution`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer solution as a standalone term or, depending on the context, definitive, optimal, best, or last solution.

[Official entry](https://developers.google.com/style/word-list#final-solution)

<a id="term-fintech"></a>
## `fintech`

**Scope:** `general`  
**Rule:** Write out on first mention: financial technology (fintech). Do not use FinTech or fin-tech.

[Official entry](https://developers.google.com/style/word-list#fintech)

<a id="term-firewalls"></a>
## `firewalls`

**Scope:** `general`  
**Rule:** Do not use in Compute Engine or networking documentation. Prefer firewall rules. Exception: If you're explaining how firewall rules work, you can explain that every network has an implied virtual distributed firewall. Outside of Compute Engine or networking documentation, the term firewalls is acceptable.

[Official entry](https://developers.google.com/style/word-list#firewalls)

<a id="term-first-class"></a>
## `first class, first-class, first-class citizen`

**Scope:** `do-not-use`  
**Rule:** Do not use first class or first-class citizen. Prefer another term that's appropriate for the context, such as higher-order, anonymous, or nested, or loosely describe the specific characteristics or features of the entity, resource, language, or framework.

[Official entry](https://developers.google.com/style/word-list#first-class)

<a id="term-following"></a>
## `following`

**Scope:** `general`  
**Rule:** It's not necessary to use a noun after following unless it helps provide clarity and enables accessibility. See Tables.

[Official entry](https://developers.google.com/style/word-list#following)

<a id="term-foo"></a>
## `foo`

**Scope:** `use-with-caution`  
**Rule:** Avoid when possible even though it's a common term in the developer community. Prefer a clearer and more meaningful placeholder name.

[Official entry](https://developers.google.com/style/word-list#foo)

<a id="term-for-example"></a>
## `for example`

**Scope:** `general`  
**Rule:** When you introduce an example using the phrase for example, follow the phrase by a comma. For clarity, when introducing an example, separate the example using dashes, commas, or parentheses from the rest of the sentence as appropriate, or introduce the example in a separate sentence.

[Official entry](https://developers.google.com/style/word-list#for-example)

<a id="term-for-instance"></a>
## `for instance`

**Scope:** `use-with-caution`  
**Rule:** Do not use the phrase for instance to introduce examples to avoid confusion with the noun instance. Prefer for example, like, or such as.

[Official entry](https://developers.google.com/style/word-list#for-instance)

<a id="term-frontend"></a>
## `frontend`

**Scope:** `general`  
**Rule:** Use the heading form; do not use front-end or front end.

[Official entry](https://developers.google.com/style/word-list#frontend)

<a id="term-functionality"></a>
## `functionality`

**Scope:** `use-with-caution`  
**Rule:** Use with caution. With respect to hardware or software, functionality refers to a set of associated functions or capabilities and how they work. However, the word is sometimes overused, especially when the intended meaning is capabilities or features.

[Official entry](https://developers.google.com/style/word-list#functionality)

<a id="term-future"></a>
## `future, in the future`

**Scope:** `use-with-caution`  
**Rule:** Avoid in timeless documentation because this word or phrase can become outdated.

[Official entry](https://developers.google.com/style/word-list#future)
