# C terminology — 1 of 3

Scope labels are cumulative. `general` means no product-only marker was
present; a project-specific rule can still override this entry.

<a id="term-can"></a>
## `can`

**Scope:** `general`  
**Rule:** Use can in the following ways: To convey permission or ability (for example, "You can access the server"). To refer to an optional action (for example, "You can also view logs with the Log Viewer"). To describe a possible outcome (for example, "The process can take 30 minutes"). For information about clarifying who's performing an action, see Active voice.

[Official entry](https://developers.google.com/style/word-list#can)

<a id="term-canary"></a>
## `canary`

**Scope:** `use-with-caution`  
**Rule:** Do not use **canary** as a verb or **canarying**. Prefer a more precise term to
the jargon **canary** or **canary testing**; if retained, define it at first use and apply
it consistently.

[Official entry](https://developers.google.com/style/word-list#canary)

<a id="term-cell-phone"></a>
## `cell phone, cellphone`

**Scope:** `do-not-use`  
**Rule:** Do not use. Prefer mobile phone, or if you're talking about more than phones, then use mobile device. Acceptable to use phone (without mobile) when the context is clear.

[Official entry](https://developers.google.com/style/word-list#cell-phone)

<a id="term-chapter"></a>
## `chapter`

**Scope:** `general`  
**Rule:** For documentation that isn't in the form of a book, do not use the term chapter. Instead, refer to documents, pages, or sections.

[Official entry](https://developers.google.com/style/word-list#chapter)

<a id="term-check"></a>
## `check`

**Scope:** `use-with-caution`  
**Rule:** Do not use to refer to marking a checkbox. Prefer select.

[Official entry](https://developers.google.com/style/word-list#check)

## `checkbox`

## `choose`

**Scope:** `general`

<a id="term-chubby"></a>
## `chubby`

**Scope:** `do-not-use`

<a id="term-clear"></a>
## `clear`

**Scope:** `general`  
**Rule:** Use (as a verb) to refer to clearing a check mark from a checkbox.

[Official entry](https://developers.google.com/style/word-list#clear)

<a id="term-cli"></a>
## `CLI`

**Scope:** `use-with-caution`  
**Rule:** Do not use CLI generically to refer to a command-line interface. Instead, refer to the specific command-line interface, such as the Google Cloud CLI.

[Official entry](https://developers.google.com/style/word-list#cli)

<a id="term-click"></a>
## `click`

**Scope:** `general`  
**Rule:** In a pointer-based desktop interface, use **click** for buttons, links, list
items, and radio buttons; do not use **click on**. **Click in** is acceptable for a region
that needs focus, but not for a control or link. Hyphenate **right-click**, **left-click**,
and **double-click**.

[Official entry](https://developers.google.com/style/word-list#click)

<a id="term-client"></a>
## `client`

**Scope:** `general`  
**Rule:** In REST and RPC API documentation, **client** means the client application the
developer is writing. Do not use it for **client library**; prefer **library**.

[Official entry](https://developers.google.com/style/word-list#client)

<a id="term-cloud"></a>
## `Cloud`

**Scope:** `use-with-caution, google-cloud-only`  
**Rule:** Do not use as short for Google Cloud. For generic references such as the cloud or hybrid cloud, use lowercase.

[Official entry](https://developers.google.com/style/word-list#cloud)

<a id="term-gcp-console"></a>
## `Cloud console`

**Scope:** `do-not-use, google-cloud-only`  
**Rule:** Do not use. Instead, refer to the full name Google Cloud console. If you aren't discussing any other console (such as the Google Admin console), you can abbreviate to the console after first mention. Use the before the tool name.

[Official entry](https://developers.google.com/style/word-list#gcp-console)
