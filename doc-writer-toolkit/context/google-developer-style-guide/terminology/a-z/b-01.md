<a id="term-bare-metal"></a>
## `bare metal`

**Scope:** `general`  
**Rule:** Lowercase except at the beginning of a sentence, heading, or list item. Hyphenate when used as a compound modifier, such as bare-metal server.

[Official entry](https://developers.google.com/style/word-list#bare-metal)

<a id="term-base64"></a>
## `base64`

**Scope:** `general`  
**Rule:** Lowercase except at the beginning of a sentence, heading, or list item. Otherwise, capitalize Base64 only if it's part of a formal name. Write base64 in code font only if it's a string literal or otherwise quoted from code.

[Official entry](https://developers.google.com/style/word-list#base64)

<a id="term-below"></a>
## `below`

**Scope:** `use-with-caution`  
**Rule:** Do not use for a range of version numbers. Prefer earlier. Do not use to refer to a position in a document. Prefer later or following. Do not use to refer to a position in the UI. Instead, write instructions that avoid directional language. Acceptable to use below in set phrases such as below (the) average, below the mean, below zero. Acceptable to use below in a non-directional way, such as when describing a hierarchy.

[Official entry](https://developers.google.com/style/word-list#below)

[Official entry](https://developers.google.com/style/word-list#best-effort)

## `between versus among`

**Scope:** `general`  
**Rule:** It's fine to use between when talking about more than two things; however, between isn't interchangeable with among. Use between when you're talking about two or more distinct things: Use among when you're talking about things that are part of a group or things that aren't distinct: More examples:

<a id="term-billing-charges"></a>
## `billing charges`

**Scope:** `use-with-caution`  
**Rule:** Do not use billing charges to mean charges that appear on a bill. Prefer billed charges. Use billing charges to describe the cost of creating the bill.

[Official entry](https://developers.google.com/style/word-list#billing-charges)

<a id="term-black-box"></a>
## `black-box`

**Scope:** `use-with-caution`  
**Rule:** Avoid using black-box, blackbox, or black box to describe monitoring and testing. Consider using a more precise term for clarity. For monitoring, use synthetic monitoring. For testing, use opaque-box testing.

[Official entry](https://developers.google.com/style/word-list#black-box)

<a id="term-blacklist"></a>
## `blacklist, black list, black-list`

**Scope:** `do-not-use`  
**Rule:** Do not use blacklist, whitelist, and graylist. Prefer more precise terms that are appropriate for your domain. Instead, replace verbs such as blacklisted with phrases that accurately convey the relevant action. For example: If the command or code that you're documenting uses one of these words, then use the words only in direct reference to the code items (formatted as code), and make it clear what you're referring to.

[Official entry](https://developers.google.com/style/word-list#blacklist)

## `blind`

**Scope:** `use-with-caution`  
**Rule:** Avoid using blind to or blind eye to. Prefer more precise terms like ignore, unaware of, disregard, avoid, or reject. Avoid using blind writes. Prefer a more precise phrase, such as a write operation without a read operation.
