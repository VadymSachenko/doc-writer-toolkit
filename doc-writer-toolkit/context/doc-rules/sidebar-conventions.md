# sidebar-conventions.md

Defines how the `document-section` orchestrator reads and updates the Docusaurus sidebar file for a section. The sidebar file itself lives in the host project (not this plugin); this file explains how to locate it, parse it, and safely insert or reorder entries.

## Locating the sidebar file

1. Read `Sidebar file:` from the host project's `CLAUDE.md` "Documentation toolkit configuration" block.
2. If not declared, default to `sidebars.ts` at the project root.
3. If that file doesn't exist, check `sidebars.js`. If neither exists, stop and ask the user.

## Docusaurus sidebar formats

Docusaurus sidebars are declared in TypeScript or JavaScript. Two common patterns:

### Autogenerated (simple)

```ts
const sidebars: SidebarsConfig = {
  docs: [{ type: 'autogenerated', dirName: '.' }],
}
```

If the sidebar is fully autogenerated, **do not edit it** — Docusaurus builds it from the `sidebar_position` frontmatter in each doc file. Instead, set `sidebar_position:` in the page's frontmatter per the approved plan's `sidebarOrder`. Report to the user that the sidebar is autogenerated and that `sidebar_position` was set instead.

### Manual category entries

```ts
const sidebars: SidebarsConfig = {
  docs: [
    {
      type: 'category',
      label: 'Transactions',
      items: [
        'transactions/transactions',
        'transactions/filter-transactions',
        'transactions/create-payin',
      ],
    },
  ],
}
```

For manual sidebars, insert or reorder entries within the category that matches this section.

## Update rules

1. **Read the current sidebar file** before making any changes.
2. **Locate the section's category** by matching the category `label` or `dirName` to the section folder name.
3. **Insert new pages** at the position declared in the approved plan's `sidebarOrder`. If `sidebarOrder` is a flat list, use its order directly. If the sidebar already has the entry, do not duplicate it.
4. **Reorder existing entries** only within this section's category — never reorder entries in other categories.
5. **Do not delete sidebar entries** for pages not in the approved plan (they may be intentionally outside this run's scope).
6. **Do not add** sidebar config keys (`collapsible`, `collapsed`, `className`, etc.) not already present for the section — copy the pattern the existing category uses.
7. After editing, verify the file is valid TypeScript/JavaScript syntax before saving (check bracket balance; do not run the build).

## Setting sidebar_position frontmatter (autogenerated sidebars)

For each page in the approved plan, set `sidebar_position:` in its frontmatter to the 1-based position from `sidebarOrder`. If a `sidebar_position` already exists in the file, update it.

```yaml
---
title: Filter transactions
sidebar_position: 2
---
```

## Example: inserting a new page in a manual sidebar

Approved plan `sidebarOrder`: `["transactions", "filter-transactions", "create-payin"]`

Before:
```ts
items: [
  'transactions/transactions',
  'transactions/filter-transactions',
],
```

After adding `create-payin` at position 3:
```ts
items: [
  'transactions/transactions',
  'transactions/filter-transactions',
  'transactions/create-payin',
],
```

Do not add entries for pages that the writer skill has not yet saved (`status` not `clean` in the ledger).
